# iBreeze — Project Notes

iOS comic reader that keeps **Pixiv-SwiftUI's look** and **Breeze's plugin system** as its core.
Written in SwiftUI; the plugin runtime is a from-scratch Swift/JavaScriptCore reimplementation
of Breeze's QuickJS runtime (see `README.md` for the user-facing overview).

## Build & test

There is **no local macOS toolchain** — everything is verified on GitHub Actions:

```
.github/workflows/build.yml   # macos-26 runner, Xcode 26
  xcodegen generate
  xcodebuild test  -> iOS Simulator (unit + smoke tests)
  xcodebuild archive (unsigned) -> iBreeze-unsigned.ipa artifact
```

Project file is generated by **XcodeGen** from `project.yml`; `*.xcodeproj` is gitignored.
Add files under `iBreeze/` or `iBreezeTests/` and regenerate — no manual project edits.

Run tests locally only if you have a Mac:

```
xcodegen generate
xcodebuild test -project iBreeze.xcodeproj -scheme iBreeze \
  -destination 'platform=iOS Simulator,name=iPhone 17'
```

### Smoke tests

`iBreezeTests/PluginSmokeTests.swift` downloads the real `breeze-plugin-ehentai` bundle from
jsDelivr and drives it through the runtime. They are opt-in:

```
TEST_RUNNER_IBREEZE_SMOKE=1            # install + getInfo + image bytes
TEST_RUNNER_IBREEZE_SMOKE_NETWORK=1    # + real list/detail/chapter over the network
```

CI sets both. Locally they are skipped so offline runs stay green.

## Local JS verification (no Mac needed)

```
node Tools/plugin-js-harness.mjs                                  # 50 self-checks
node Tools/plugin-js-harness.mjs <bundle.cjs> <fnPath> [payload]  # run a real plugin bundle
node Tools/generate-app-icon.mjs                                  # regenerate the app icon
```

Real-network runs need the proxy on this machine (Node's `fetch` ignores `HTTP_PROXY` unless told):

```
NODE_USE_ENV_PROXY=1 node Tools/plugin-js-harness.mjs <bundle.cjs> getLatestData '{"page":1}'
```

The harness boots the same injection chain as the app inside a bare `node:vm` context
(JavaScriptCore-like: no web globals), stubs the Swift host functions, and can serve a local
HTTP endpoint to exercise the full `fetch -> Response -> BreezeHtml` path. Use it before
pushing whenever you touch the JS layer.

## Architecture

```
iBreeze/
├── App/                 entry, tabs, AppRoute + destinations
├── DesignSystem/        theme constants, glassSurface, cards, image view
├── Features/            Home / Search / Favorites / ComicList / ComicDetail / Reader / Settings / PluginStore
├── PluginKit/
│   ├── Runtime/         PluginRuntime (JSContext), PluginRuntimeThread, PluginHostBridge,
│   │                    PluginCrypto(+Routes), PluginHTTPClient, PluginTimerCenter, PluginJSLayer
│   ├── Models/          manifest + contract models (JSONValue for loose fields)
│   ├── Store/           PluginStore (files), PluginInstaller, PluginRepository, PluginDownloader
│   └── Source/          PluginSource (typed fnPath calls), PluginRegistry (app-facing)
├── Core/                storage (history/favorites), image loader, Chinese converter
└── Resources/PluginRuntime/   injected JS (see its NOTICE.md)
```

## Gotchas (hard-won)

- **Plugin JS must run on a big-stack thread.** `PluginRuntimeThread` gives 16 MB; with GCD's
  default worker stack, plugins bundling axios die with `Maximum call stack size exceeded`
  on real requests. Do not switch back to `DispatchQueue`.
- **`BreezeHtml` is required, not optional.** Plugins scrape HTML right after `getInfo`;
  missing it yields `ReferenceError: BreezeHtml is not defined`.
- **Injection order matters**: `04_runtime_base_polyfills` *before* `00_bootstrap` (04 provides
  `Buffer`/`Blob`/`FormData`), host shim *after* `99_exports` (it overwrites `bridge`/`console`).
- **Binary crosses the bus as a base64 envelope** (`{ "__ibreezeBinary": ... }` on returns,
  byte arrays on arguments). Use `invokeData` for binary-returning fnPaths.
- **`extern` round-trips**: return whatever the plugin gave back on the next call.
- `Resources/PluginRuntime` is a **folder reference** in `project.yml`; keep it out of the
  main source glob or the JS files get compiled as resources twice.
